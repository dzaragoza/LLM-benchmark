### Session 34, addendum 20 - code_edit.py: the agent's editing tool (verify -> apply -> atomic write -> fsync -> re-read -> assert)

THE PROBLEM: conversational editing (heredocs, hand-typed diffs) fails on whitespace, duplicate matches, and silent partial writes - the v4.2/v4.3 reworks burned more time on patch mechanics than on the protocol itself. THE TOOL: code_edit.py makes an edit a TRANSACTION. Blocks are (replace, old, new) / (delete, old) / (insert_before/insert_after, anchor, new), verified in order against the CURRENT buffer (a later block can rely on an earlier one) - any missing or AMBIGUOUS target (2+ matches) is a hard error and NOTHING is written (all-or-nothing). The write is atomic (temp file + os.replace), then fsync of the file AND its directory (the rename is crash-atomic; the dir fsync makes the rename durable), then the file is RE-READ from disk and the post-conditions asserted. No regex, no fuzzy matching - the caller states exactly what changes; ambiguity is a coin-flip refused. 6 tests cover the guarantees: sync-to-disk, loud failure with the file untouched, ambiguity rejection, ordered blocks, all-or-nothing (a failing second block does not leak the first), and no temp-file litter. The tool is its own first customer: the ruff E501 fixes in this very addendum were applied through it.

### Session 34, addendum 24 - Q4 rung choice: Q4_K_M over Q4_0; the rationale on record

THE QUESTION (the author: "what is the best Quant suffix for q4? I was thinking of using _0, same as q8"): the Q4 test of context-over-parameters needs a 4-bit encoding, and the suffix choice determines what the ladder measures.

THE RULING: **Q4_K_M**, recorded here for the report. The reasoning:

1. **It is the honest instrument.** The hypothesis under test is "for this bandwidth class, context dominates - a smaller file should gain rungs (deeper KV, faster weight reads)." Q4_K_M is the community-standard best-quality 4-bit (~4.8 bpw): most tensors Q4_K, attention/output tensors Q6_K. It minimizes the confound - a rung gained is a context win, not a quant artifact. Q4_0 is the legacy bare block format (~4.5 bpw, no importance matrix, no mixed precision); its extra quality damage lands exactly on FWE counting, so a Q4_0 ladder cannot distinguish "context won" from "quant broke the counting" - the disambiguator (FWE flicker vs more passing rungs, addendum 21) loses its power.

2. **The naming-symmetry case for Q4_0 was considered and deferred.** Symmetry with Q8_0 is real (both legacy formats, a cleaner size-law baseline), and Q4_0 is slightly faster per byte at equal size - but it answers the size-law question, not the practical one. If the size-law baseline is wanted later, Q4_0 is a defensible second run, not the lead.

3. **Operational: the Qwen lineage has premade Q4_K_M files on the Hub for every size** - no local llama-quantize, no f16 staging, no extra disk (relevant after the disk cleanup). Where a premade file is missing, the pipeline quantizes from f16 locally (llama-quantize + temporary f16 on disk).

THE MECHANISM (already in the tree, addendum 23 follow-on): `--rung` takes any suffix - `--rung Q4_K_M` or `--rung Q4_0` - so the choice is a flag, not a code change. The run keeps its own state/results pair: `--state-file benchmark-state-q4.json --results-file benchmark-results-q4.json`.

THE QUEUE (the author's plan, on record): (1) the lineage-2 run finishes; (2) each model re-measured directly at its optimal rung with the smaps census live (resident_gib becomes the authoritative memory number for the pickers); (3) the Q4 run at Q4_K_M.

THE BASELINE TO BEAT: Qwen3.5-0.8B Q8_0, scored 105,472 tok at 2.53 GiB cold (addendum 21). The Q4 question is whether a 0.8B-class model at ~0.45 GiB of weights reaches comparable or better depth+s cost - and whether the 4B-class models, freed from ~4.3 GiB of weight reads, climb past 65,536.

### Session 34, addendum 26 - on record for a future study: coin-toss sampling for the worst conversation

THE QUESTION (the author, statistics, for a future study and for learning): "I want to do the minimum sampling to find a conversation that drops the wps the most in a portion of the models. How do we do that?"

THE PROBLEM CLASS: worst-arm identification (best-arm identification, inverted) - each conversation is an arm with an unknown true mean worst-turn wps; the goal is the minimum, certified, at minimum bench cost. The information-theoretic wall, stated honestly: NO method can certify a global minimum without at least one measurement of every conversation - an unmeasured conversation could be the worst, and nothing about the others changes that. The full treatment (successive elimination with confidence bounds) was sketched: sample every arm once, eliminate arms whose upper bound falls below the leader's lower bound, re-sample survivors - cost concentrates on the close calls near the bottom; sample budget per surviving pair scales as (c*sigma/delta)^2 for the wps gap delta that matters. Screening-with-a-cheap-proxy (2-turn probes, then full runs on the bottom bracket) and pooling priors across models (the corpus is fixed; pathological conversations correlate across models) reduce the cost ~10x but keep the every-conversation guarantee.

THE RULING (the author: "let's go with 3 with a coin toss, 50% confidence"): PROBABILISTIC SAMPLING at exactly 50%. The design, for the future study: flip a fair coin per conversation; bench the conversation only on heads. The probability that the global worst conversation is inside the measured set is EXACTLY 50% - no order statistics, no approximation: the worst is in the sample iff its own coin came up heads. Per model this benches ~half the corpus (~25 of 50); the reported number is "the worst among a uniformly random half," with the honest caveat stated in the report: "there is a 50% probability that the corpus's worst conversation went unmeasured." The strength of the design is that it is assumption-free - no proxy-validity claim, no cross-model pooling claim - and the coin is reproducible from a logged seed. The plan for the study writeup: pre-register the coin toss (the seed, the assignment), report the sampled minimum with its per-conversation provenance, and scope every conclusion to the sampled half.

THE FLICKER RULE (the author: "Let's make any flipping run invalid"): FWE verdicts must be MONOTONE - depth only gets harder, so a run that PASSES FWE at a deep rung while FAILING at a shallower one is an n=1 boundary coin-flip and the whole run is INVALID. THE HONEST SCOPE NOTE: within a single ladder the gallop+binary-search structure keeps verdicts monotone BY CONSTRUCTION (every pass becomes lo, every fail becomes hi, midpoints stay between) - so the in-ladder hook is a guard, and the real catches come from re-reading stored ladders (cross-grid, the two hand-invalidated families being the precedent the rule now automates). 3 tests pin the detector (flicker pair caught, monotone shapes stand, unmeasured rungs ignored) and the invalidation path (score 0, reason string, loud print). 41 tests total.
